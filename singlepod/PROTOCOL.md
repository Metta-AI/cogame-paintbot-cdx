# Paintbot WASM policy ABI v1

A policy is one core WebAssembly module (`.wasm`), optionally a WASI Preview 1
reactor. The game loads it with Wasmtime 48. Each episode seat gets a fresh
instance, even when multiple seats use the same file. The only available imports
are WASI Preview 1; no filesystem, environment variables, sockets, or inherited
stdio are granted. The included baseline imports only WASI output/exit functions.

Export these functions and memory (all pointers and lengths are `i32`):

| Export | Signature | Purpose |
| --- | --- | --- |
| `memory` | linear memory | Exchange observations and actions |
| `_initialize` | `() -> ()`, optional | Reactor initialization, called once |
| `paintbot_init` | `(slot: i32) -> ()` | Initialize the policy for its episode seat |
| `paintbot_buffer` | `(size: i32) -> i32` | Return a writable buffer for the next observation |
| `paintbot_step` | `() -> i32` | Process the buffer and return the reply-buffer pointer |
| `paintbot_output_size` | `() -> i32` | Return reply-buffer length |

The host writes exactly `size` bytes to the observation buffer, then calls
`paintbot_step`, then `paintbot_output_size`. The reply buffer must remain valid
until the next policy call. Policies retain their own memory between frames.

Observations are the original binary **Bitworld Sprite v1** player frames;
see [the game protocol](../docs/PROTOCOL.md). Fog of war, walkability, labels,
own-state markers, pickups and sounds are generated by the existing server.
Sprite pixel payloads are disabled. Frames are passed in order without draining
or dropping queued frames. Tick advancement is encoded in the Sprite protocol.

Replies are a little-endian `u32` packet count, followed by, for each packet,
a little-endian `u32` byte length and that many packet bytes. Zero packets means
keep the previous held input. The supported packets are:

- Input: `0x84`, followed by one actuator-mask byte.
- Chat: `0x81`, a little-endian `u16` ASCII byte length, then the text.

The host owns identity, connection setup, sprite suppression and fast-mode ready
signals. A guest cannot claim another seat. The baseline returns the existing
policy's changed input masks; its decision logic is not reimplemented.

Limits per instance: 256 MiB linear memory, 20 billion fuel units per call,
60 seconds for initialization and 30 seconds per observation. The giant-map
baseline's initial navigation field exceeds a two-billion-fuel budget. A call
that traps, runs out of fuel, exceeds a deadline, or returns invalid pointers or
packets terminates that seat and fails the episode with explicit attribution.
Observation buffers are capped at 16 MiB; replies at 64 KiB and 64 packets.
Policies have no ambient credentials. Host-side downloads use the game pod's
normal AWS credential chain when given `s3://` URIs.

## Coworld seat files

Set `COGAME_PLAYER_SEATS_URI` to a `coworld-player-seats/1` JSON document:

```json
{
  "schema": "coworld-player-seats/1",
  "seats": [{
    "slot": 0,
    "file_uri": "s3://my-bucket/policies/baseline.wasm",
    "content_hash": "sha256:<64 hexadecimal characters>",
    "size_bytes": 12345,
    "log_uri": "file:///coworld/logs/policy_agent_0.log",
    "artifact_uri": "file:///coworld/policy_artifact_0.zip"
  }],
  "player_status_uri": "file:///coworld/player_status.json"
}
```

Seats must be ordered and contiguous starting at zero. Every file is bounded and
verified against its declared byte size and SHA-256 before the game starts.
`file://`, local paths, HTTPS URLs (including presigned S3 URLs), and `s3://`
are supported. Coworld normally downloads and verifies policy objects itself
and supplies staged `file://` URIs, so the game needs no S3 access in that path.
Logs and statuses are local output files. Optional policy-artifact ZIPs are not
produced by this ABI. A failed guest is reported through
`COGAME_PLAYER_FAILURE_URI` and `player_status_uri`.
